# عامل Instaloader على جهاز في البيت (حل الحجب)

إنستقرام يحجب بسرعة عناوين مراكز البيانات، أي خوادم Vercel و Railway وأي سحابة. عنوان الإنترنت المنزلي عنوان سكني، وإنستقرام يحجبه أقل بكثير. لذلك يعمل العامل على جهاز عندك، ويصل إليه Vercel عبر Cloudflare Tunnel:

```
Vercel (اللوحة)  ──https──▶  Cloudflare  ◀──نفق صادر──  جهازك: ig-worker + cloudflared  ──▶  إنستقرام
```

- **مجاني:** Cloudflare Tunnel مجاني، والجهاز يمكن أن يكون أي كمبيوتر أو Raspberry Pi يبقى شغالاً.
- **آمن:** النفق يتصل من جهازك إلى Cloudflare، فلا تفتح أي منفذ في الراوتر، وعنوان بيتك لا يظهر لأحد. كل طلب يحتاج `WORKER_SHARED_SECRET`.

## ثلاث طبقات ضد الحجب (تعمل تلقائياً)

1. **العامل يبطّئ نفسه:** طلب كل 3 ثوانٍ تقريباً مع تأخير عشوائي، وبدون تسجيل دخول.
2. **تدوير المخارج داخل العامل:** إن أضفت بروكسيات سكنية في `PROXY_URLS`، يبدأ العامل بعنوان البيت ثم البروكسيات. أي مخرج يُحجب يرتاح 15 دقيقة، وتتضاعف المدة مع كل حجب متتالٍ حتى 6 ساعات، وينتقل الطلب نفسه للمخرج التالي.
3. **التحويل بين المزوّدين في اللوحة:** إذا ارتاحت كل مخارج العامل، تنتقل المهمة تلقائياً إلى Graph API أو Apify إن كانت مضبوطة، ثم تعود للعامل المجاني عندما يجهز.

## الخطوات

### 1. Cloudflare Tunnel

1. أنشئ حساباً مجانياً على cloudflare.com وأضف نطاقك. يلزمك نطاق تملكه، ولو كان رخيصاً.
2. من **Zero Trust → Networks → Tunnels → Create a tunnel** اختر **Cloudflared**، وسمّه `ig-worker`.
3. انسخ الـ **token** الذي يظهر في أمر التثبيت (النص الطويل بعد `--token`).
4. في **Public Hostname** أضف:
   - Subdomain: `worker` (مثلاً)، والنطاق: نطاقك
   - Service: `HTTP` و `ig-worker:8000`

### 2. على جهازك

ثبّت Docker، ثم:

```bash
git clone https://github.com/inzohussein-blip/spir-scraper.git
cd spir-scraper/deploy/home-worker
cp .env.example .env
```

عبّئ في `.env`:
- `WORKER_SHARED_SECRET`: قيمة طويلة عشوائية (`openssl rand -hex 32`)، وهي نفسها التي ستضعها في Vercel.
- `TUNNEL_TOKEN`: من الخطوة السابقة.
- `PROXY_URLS`: اختياري، ويُترك فارغاً في البداية.

```bash
docker compose up -d
```

الحاويتان مضبوطتان على `restart: unless-stopped`، فتعودان للعمل وحدهما بعد إعادة تشغيل الجهاز.

### 3. في Vercel

من **Settings → Environment Variables**:

| المتغير | القيمة |
|---|---|
| `WORKER_URL` | `https://worker.نطاقك.com` |
| `WORKER_SHARED_SECRET` | نفس القيمة التي في `.env` |
| `WORKER_RATE_PER_MINUTE` | `15` (اختياري) |

ثم **Redeploy**.

## الفحص

```bash
curl https://worker.نطاقك.com/health
# {"status":"ok","exits":1,"ready":1}

curl -H "x-worker-secret: $WORKER_SHARED_SECRET" https://worker.نطاقك.com/status
# حالة كل مخرج: هل هو جاهز، ومتى يعود إن كان يرتاح، وآخر خطأ
```

`/health` عام لكنه لا يعرض إلا الأعداد. أما `/status` فيحتاج السر، ولا يعرض كلمات مرور البروكسيات أبداً.

في اللوحة، **الإعدادات** تعرض حالة المزوّدين، ويرسل تلكرام تنبيهاً عندما يُحجب مزوّد وعندما يعود.

## إن استمر الحجب

- زِد `MIN_INTERVAL_SECONDS` إلى 5 أو 8.
- أضف بروكسياً سكنياً واحداً أو أكثر في `PROXY_URLS`، بشرط أن يكون سكنياً لا من مراكز البيانات.
- اضبط `APIFY_TOKEN` في Vercel كاحتياط، فيكمل العمل تلقائياً عند الحجب.

## محرك Spir (زحف بطيء ومجاني)

المحرك يقرأ حساباً عاماً كل دقيقة تقريباً من إنترنت بيتك، **بلا تسجيل دخول**، ويرسل ما قرأه للمنصة. صفحة **محرك Spir** تحدد السرعة وساعات الراحة والحد اليومي، وصفحة **العامل المنزلي** (`/workers`) تعرض الأجهزة وعناوينها والبروكسيات وخطوات التشغيل مفصّلة لكل نظام.

ثلاث طرق، كلها تتصل بالمنصة من البيت (لا يُفتح أي منفذ، ولا يحتاج Cloudflare Tunnel):

| الطريقة | متى تناسبك | البروكسيات |
|---|---|---|
| **إضافة المتصفح** | الأسهل: فعّل «شغّل المحرك من هذا المتصفح» في إعدادات الإضافة (0.2.0+). تعمل والمتصفح مفتوح | لا (اتصال البيت فقط، حتى لا تتغير جلستك على إنستقرام) |
| **البرنامج بدون Docker** | 24 ساعة على حاسوب أو Raspberry Pi: ملف واحد `spir-worker.py` يحتاج Python 3.9+ فقط | نعم، من صفحة العامل المنزلي |
| **Docker** | لمن يستعمله: `docker compose --profile engine up -d ig-engine` | نعم |

**البرنامج:** نزّله من صفحة العامل المنزلي، وأنشئ مفتاحاً هناك، ثم:

```
python spir-worker.py --platform https://spir-scraper.vercel.app --key sk_...
```

**أو ملف exe لويندوز (خيار إضافي، بلا تثبيت Python):** زر «تنزيل spir-worker.exe» بجانب زر الـ py في الصفحة نفسها، والملفات وبصماتها (SHA256SUMS.txt) في [إصدار home-programs](https://github.com/inzohussein-blip/spir-scraper/releases/tag/home-programs). افتحه بنقرة مزدوجة فيسأل مرة واحدة عن رابط المنصة والمفتاح ويحفظهما في `~/.spir-worker-exe.json`، أو شغّله بالخيارات نفسها: `spir-worker.exe --platform ... --key ...`. الملف غير موقّع، فقد يقول ويندوز «Windows protected your PC»: More info ← Run anyway. يُبنى تلقائياً من `main` كلما تغيّر البرنامج (workflow «Home programs»). ملف الـ py باقٍ كما هو.

الصفحة تشرح تشغيله تلقائياً على Windows (مجلد startup) و Mac (nohup) و Linux (خدمة systemd).

**البروكسيات وتغيير الـ IP:**
- تُضاف من صفحة العامل المنزلي، وتُحفظ مشفّرة، وتصل للبرنامج وحدها خلال دقائق.
- البرنامج يوزّع القراءة على اتصال البيت والبروكسيات، والمخرج الذي يرفضه إنستقرام يرتاح 15 دقيقة وتكمل البقية.
- البروكسي المتنقل الذي له **رابط تغيير IP** يظهر بجانبه زر «غيّر IP».
- «افحص العناوين» يجعل كل جهاز يفحص عنوانه العام (وعنوان كل بروكسي) ويعرضه.
- بعد تغيير الشبكة أو الـ IP، «أنهِ الاستراحة الآن» يعيد المحرك فوراً.

**كيف يعمل:**
- يبدأ من البذور، ويستخرج من كل حساب من يذكرهم (@ في البايو والمنشورات، وروابط إنستقرام)، ويقرأهم بالأولوية: من ذكرهم حساب في مجالك أو أكثر من حساب أولاً.
- إن لم يطابق الحساب كلماتك لا يُقبل ولا يُتبع من يذكرهم، فيبقى الزحف في مجالك.
- المقبولون يُرسلون للمشروع كعملاء على دفعات (25)، من نفس البيانات المقروءة، فلا يُدفع شيء لـ Apify.
- إن رفض إنستقرام يستريح المحرك 30 دقيقة، ثم ساعة، ثم ساعتين… حتى 12 ساعة، ويصلك تنبيه.

**السرعة المقترحة:** حساب كل 60 ثانية مع 20 ثانية عشوائية، وحد 800 يومياً، وراحة من 2 إلى 7 صباحاً.
