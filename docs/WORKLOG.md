# سجل العمل: مراجعة المشروع وإصلاحه ونشره (22 نوفمبر 2026)

هذا الملف يوثّق كل ما تم في جلسة العمل مع Claude: من تحليل المشروع، إلى تحديث المكتبات وسد الثغرات، وحل مشكلة الحجب، ونشره على Vercel.

---

## 1. تحليل المشروع (نقطة البداية)

**ما هو المشروع:** منصة لجمع العملاء المحتملين من البيانات العامة على إنستقرام. لها نواة واحدة تعمل من أربع واجهات:
- الطرفية (CLI)
- REST API
- خادم MCP لـ Claude
- لوحة ويب

وتصدّر النتائج إلى Google Sheets أو CSV أو XLSX.

**الهيكل:**

| المجلد | الدور |
|---|---|
| `apps/web` | Next.js: اللوحة، و `/api/v1`، و `/api/mcp`، و OAuth، و cron، و webhook تلكرام. هذا ما يُنشر على Vercel |
| `apps/cli` | أمر `scrapers` في الطرفية، ويشمل خادم MCP المحلي |
| `packages/core` | المهام والاستخراج والموجّه بين المزوّدين والإيقاف |
| `packages/providers` | العامل (Instaloader) و Apify و Graph API |
| `packages/exporters` | CSV و XLSX و Google Sheets |
| `packages/ai` | التقييم بـ Claude |
| `packages/mcp` | أدوات وموارد MCP |
| `packages/api` | REST API (Hono + OpenAPI)، ويُخدَم من داخل `apps/web` |
| `packages/runtime` | يجمع كل شيء من متغيرات البيئة |
| `packages/db` | مخطط Drizzle والـ migrations |
| `services/ig-worker` | Python 3.14 + FastAPI + Instaloader، ويعمل خارج Vercel |

**التقييم:**

نقاط القوة:
- تصميم بنواة واحدة.
- أدوات حديثة: Turbo و Drizzle و pg-boss و Hono.
- اهتمام بالخصوصية: قائمة إيقاف مشفّرة، ومدة احتفاظ، و RLS، وسجل نشاط.
- اختبارات قوية: وحدة، وتكامل على Postgres، و e2e للوحة.
- CI فيه فحص أمني.

نقاط الانتباه:
- المخاطرة القانونية: شروط Meta وقوانين حماية البيانات.
- مكتبة `exceljs` مهجورة.
- إنستقرام يحجب عناوين السحابة.

**المنصة الموصى بها:**
- Vercel للوحة والـ API و MCP.
- Neon لقاعدة البيانات.
- العامل على جهاز في البيت.

## 3. سد الثغرات في الكود

| الثغرة | الملف | الإصلاح |
|---|---|---|
| إعادة توجيه مفتوحة: `/\evil.com` كان يتجاوز فحص `next` بعد الدخول | `apps/web/lib/tokens.ts` (`safeNext`) | يُرفض أي مسار فيه `\` أو `//` أو رموز تحكم، مع اختبارات |
| سر الـ cron يُقارن بمقارنة عادية | `apps/web/lib/drain.ts` | مقارنة بزمن ثابت (`safeEqual`) |
| رموز MCP بلا تحقق من الجهة | `apps/web/lib/mcp-auth.ts` | يُرفض الرمز إن لم يكن `aud` هو `/api/mcp` لهذا الموقع |
| رمز التجديد (refresh token) يُستخدم بلا حد | `apps/web/app/api/oauth/token/route.ts` | يُستخدم مرة واحدة ثم يُستبدل (OAuth 2.1) |
| زر الرفض في OAuth لا يتحقق من رابط العودة | `apps/web/app/oauth/authorize/page.tsx` | يُعاد التحقق من أن الرابط مسجّل للعميل |
| عنوان IP لحماية الدخول من ترويسة يتحكم بها الزائر | `apps/web/lib/audit.ts` | يُقرأ أولاً من `x-real-ip` التي تضعها المنصة |
| ترويسات أمان ناقصة | `apps/web/next.config.ts` | أُضيفت HSTS و Permissions-Policy و CSP (`frame-ancestors` و `base-uri` و `object-src`) |

راجعنا أيضاً هذه الأجزاء ووجدناها سليمة:
- مفاتيح API مخزّنة مشفّرة.
- العامل يقارن السر بزمن ثابت.
- رموز OAuth لا تُستخدم إلا مرة واحدة.
- PKCE مطبّق.
- هناك قفل بعد المحاولات الخاطئة: 5 لكل IP و 30 إجمالاً خلال 10 دقائق.

**تجارب حية على الخادم:**
- إعادة استخدام رمز تجديد قديم تُرفض.
- رمز MCP صادر لموقع آخر يُرفض (401).
- سر الـ cron الخاطئ يُرفض (401).
- الترويسات الجديدة ظاهرة في الرد.

> ⚠️ **بعد النشر يجب إعادة ربط Claude بـ MCP مرة واحدة**، لأن رموز التجديد القديمة صارت مرفوضة.

## 4. حل حجب إنستقرام

**المشكلة:** إنستقرام يحجب عناوين مراكز البيانات (Vercel و Railway وأي سحابة).

**الحل: ثلاث طبقات تعمل تلقائياً**

1. **العامل على جهاز في البيت عبر Cloudflare Tunnel** (`deploy/home-worker/compose.yml`):
   - عنوان البيت سكني، وإنستقرام يحجبه أقل بكثير.
   - يعمل بأمر واحد: `docker compose up -d`. لا يحتاج فتح منافذ في الراوتر، وعنوان البيت لا يظهر لأحد، وهو مجاني.
2. **تدوير البروكسيات داخل العامل** (`services/ig-worker/src/ig_worker/pool.py`):
   - يقرأ `PROXY_URLS` (عدة بروكسيات مفصولة بفواصل)، ويبدأ بعنوان البيت.
   - المخرج المحجوب يرتاح 15 دقيقة، وتتضاعف المدة مع كل حجب متتالٍ حتى 6 ساعات، وينتقل الطلب نفسه للمخرج التالي.
   - لا يُبلغ العامل عن فشل إلا إذا كانت كل المخارج ترتاح.
3. **التحويل بين المزوّدين** (كان موجوداً أصلاً): عند حجب العامل كلياً تنتقل المهمة إلى Graph API أو Apify، ثم تعود للعامل المجاني.

**مراقبة العامل:**
- `/health`: عام، ويعرض الأعداد فقط.
- `/status`: يحتاج `x-worker-secret`، ويعرض حالة كل مخرج بدون كلمات مرور البروكسيات.

**الدليل الكامل:** [docs/HOME-WORKER.md](HOME-WORKER.md)

## 5. النشر على Vercel

**مشكلة "الخدمات الأربع":** ميزة Services الجديدة في Vercel تفحص المستودع من جذره، فاكتشفت أربعة تطبيقات وأرادت بناءها كلها:
- Next.js
- FastAPI (العامل)
- Hono (الـ API)
- الـ CLI

**الحل:** ضبط **Root Directory** على `apps/web`، وإطار العمل على **Next.js**. الـ API و MCP جزء من اللوحة نفسها، والعامل لا يُنشر على Vercel.

**ما تم:**
- Claude لم يستطع إنشاء المشروع لأن Vercel رفض الطلب (403: لا صلاحية)، فأنشأه صاحب المشروع يدوياً.
- المشروع: `spir-scraper` في فريق `inzohussein-blip's projects`:
  - الإطار: `nextjs`
  - Node: `26.x`
  - البناء: من `main` فقط (`ignoreCommand` في `apps/web/vercel.json`)
  - التثبيت: `npx -y pnpm@12.21.0 install --frozen-lockfile`
- **أول بناء نجح (READY)** من الـ commit `9788dce` (دمج Pull Request #9).
- الروابط:
  - `spir-scraper.vercel.app` (الإنتاج)
  - `spir-scraper-inzohussein-blips-projects.vercel.app`
  - `spir-scraper-git-main-inzohussein-blips-projects.vercel.app`
- حماية Vercel Authentication مفعّلة بوضع "كل شيء عدا النطاقات المخصصة" (`all_except_custom_domains`). روابط المعاينة تحتاج تسجيل دخول Vercel، أما رابط الإنتاج `spir-scraper.vercel.app` فالمتوقع أن يكون مفتوحاً. لم نستطع التأكد من ذلك من بيئة Claude.
